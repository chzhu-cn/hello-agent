# E01：会话历史

## 要理解的问题

P1 的 messages 在每次 run 中新建，保存的是一次任务内部的工具循环。E01-A 将已完成的用户输入和助手回复保存在 Conversation 对象中，下一轮再次发送。模型能承接前文，是因为请求带上了历史。

本步使用纯文本偏好案例，复用 tools/llm.py 的请求与响应校验；不引入工具循环、磁盘持久化、偏好提取或摘要。Schema 放在 schemas/memory.py，入口在 sdk/e01_memory/agent.py。

## 数据流与边界

1. 新建 Conversation，其 messages 默认为独立空列表。
2. 构建请求：系统说明 + 当前会话全部历史 + 本轮用户输入。
3. 请求成功且回复通过校验后，保存本轮 user 和 assistant 两条消息。
4. 请求失败或回复无效时，不保存本轮，保留此前完整对话；不自动重试。交互模式可以继续输入。
5. 新建会话得到空历史；退出进程后历史丢失。

每轮一次模型请求，无工具执行。历史会随对话增长，目前没有输入预算或截断策略，相关内容留到 E02。会话隔离指客户端不会把 A 的历史发送给 B，不代表对服务端数据处理作出保证。

## 运行

固定演示：

```sh
uv run python -m hello_agent.sdk.e01_memory.agent
```

交互体验：

```sh
uv run python -m hello_agent.sdk.e01_memory.agent --interactive
```

输入一句虚构偏好，再追问；输入 `/new` 新建空会话，输入 `/exit` 退出。空输入忽略。沿用现有 LLM 配置，关闭 SDK 自动重试。

## 学习回顾

会话对象的存活时间决定这份历史能保留多久。只保存用户消息会丢失助手此前的回答，导致“你刚才说的第二点”这样的追问缺少依据。下一步 E01-B 将研究保存和恢复指定会话，本步先理解内存中历史的作用。

## E01-B：历史持久化

2026-09-15 用户要求继续，进入本步骤。E01-A 已提供学习回顾，未收到用户手动体验结果，不补记为已验证。

### 运行与体验

```sh
uv run python -m hello_agent.sdk.e01_memory.agent --interactive --session colors
```

输入“我最喜欢青绿色”，收到回复后输入 `/exit`。再次运行相同命令，输入“我最喜欢什么颜色？”，启动日志应显示已加载 2 条消息。换成 `--session other`，应从空历史开始。名称允许字母、数字、下划线和连字符，首字符必须是字母或数字，最多 64 字符，区分名称时建议统一用小写（Windows 文件名通常不区分大小写）。

持久化模式下 `/new` 生成并显示新会话名称，旧文件保留；之后可通过显示的名称恢复新会话。不提供 `--session` 时仍是 E01-A 的纯内存行为。

### 实现与边界

1. `tools/memory.py` 按名称读取 JSON；不存在时创建空会话，文件损坏或轮次不完整时明确退出，不覆盖原文件。
2. 启动时将文件内容通过 Pydantic 校验，恢复为 Conversation；每轮仍发送系统说明、全部历史和本轮输入。模型不会直接读取磁盘文件。
3. 在会话副本中完成本轮，写入同目录临时文件后替换目标文件；成功后才将副本作为当前会话。请求失败不写磁盘；磁盘保存失败保留此前历史，不自动重试模型请求。
4. 日志中的“回复”和消息数量表示内存中的结果；只有“已保存到磁盘”表示持久化成功。保存失败时，即使回复已显示，也不会出现在下一轮历史中。
5. `MEMORY_DIRECTORY` 由 `.env` 与 MemoryConfig 加载，默认 `.local/sessions`，相对路径基于启动目录。默认目录已加入 Git 忽略；自定义目录需自行安排版本控制排除。

JSON 保存明文用户和助手消息，不保存系统提示词或配置。此示例适用于单进程依次使用会话，不支持多个进程同时写同名会话，也不承诺断电后的持久性。完整历史仍会增长，上下文预算留到 E02；偏好提取、更新和删除留到 E01-C。

## E01-C：明确偏好的更新与删除

2026-09-16 用户要求继续，进入独立偏好实验。聊天历史记录“曾经说过什么”，偏好档案记录“当前明确保存什么”。本实验使用显式命令，不让模型自动提取或修改偏好。

```sh
uv run python -m hello_agent.sdk.e01_memory.preferences --profile demo --set 颜色 青绿色
uv run python -m hello_agent.sdk.e01_memory.preferences --profile demo --ask "我最喜欢什么颜色？"
uv run python -m hello_agent.sdk.e01_memory.preferences --profile demo --set 颜色 紫色
uv run python -m hello_agent.sdk.e01_memory.preferences --profile demo --ask "我最喜欢什么颜色？"
uv run python -m hello_agent.sdk.e01_memory.preferences --profile demo --delete 颜色
uv run python -m hello_agent.sdk.e01_memory.preferences --profile demo --show
uv run python -m hello_agent.sdk.e01_memory.preferences --profile demo --ask "我最喜欢什么颜色？"
```

预期回答依次为青绿色、紫色、不知道。`--set` 替换同名键，`--delete` 删除该键（不存在时保持不存在），`--show` 查看当前档案。设置、删除和查看不请求模型；仅 `--ask` 发起一次请求，失败不自动重试，也不修改偏好。沿用统一配置初始化，因此这些命令仍要求有效的项目配置。

文件位于 `MEMORY_DIRECTORY/preferences-<profile>.json`，与会话文件分开。档案名称沿用会话名称约束；键去除首尾空白后为 1–64 字符，值为 1–500 字符，最多 50 项。Pydantic 校验后采用临时文件替换，保存失败保留旧内容；损坏文件报错且不覆盖。默认目录被 Git 忽略，明文存储，仅支持单进程依次写入。

每次提问重新加载档案，发送系统说明、当前偏好 JSON 和问题，**不携带聊天历史，也不保存问答**。偏好以用户消息数据传入，不提升为系统指令；提示词区分数据与指令不构成完整的提示注入防御。档案由调用方显式选择，本例没有用户认证。

删除仅作用于此偏好档案，不删除 E01-B 的旧聊天、已有日志或服务端数据。如果以后把包含旧偏好的历史重新发给模型，模型仍可能从中得知旧值；本实验通过独立请求验证当前档案的更新与删除。
