# E03-A：六道固定题的最小评估

本步复用 E01 的 `chat`，只新增题目/结果 Schema 与一个运行入口，不建立通用评估框架。运行：

```sh
uv run python -m hello_agent.sdk.e03_evaluation.agent
```

使用现有 LLM 配置，每题一次请求尝试，共六次，无工具、无 SDK 自动重试。旧历史为预置数据，助手统一回复“收到”，不是实时生成。每题从独立历史副本开始，答案不会流入下一题。

| 题目 | 输入历史的要点 | 预期短答案 |
| --- | --- | --- |
| 记住颜色 | 最喜欢青绿色 | 青绿色 |
| 更新偏好 | 先喜欢红色，明确改为蓝色 | 蓝色 |
| 新会话隔离 | 空历史 | 不知道 |
| 无关历史 | 只说练习加法 | 不知道 |
| 否定不是偏好 | 不喜欢红色，未说最喜欢什么 | 不知道 |
| 跨轮追问 | 喜欢紫色，之后两轮无关话题 | 紫色 |

每题问题要求只回答颜色名称或“不知道”。判分只忽略首尾空白和末尾句号，然后和预期答案完全比较。不使用子串匹配，避免“不是青绿色”被判正确；也不使用模型自评。预期答案只参与本地判分，不作为评分提示发给模型。

这是一份严格输出契约下的小型回归集：含义正确但格式不同也会失败，需查看实际答案区分格式与事实问题。不能用六道题的通过率代表整体模型能力。

日志逐题记录 system、输入历史和问题，并输出结果 JSON：实际答案、预期答案、completed、passed、错误类型、请求尝试数、工具次数和耗时。`completed=true, passed=false` 表示成功返回正文但未通过规则；空响应或 API 错误为未完成，该题失败后仍继续后续题目。不记录原始 API 错误体以避免意外输出服务敏感信息。请求数依赖本步固定的一题一请求流程，不是通用 Agent 追踪器；未采集 token、费用或工具事件。

所有题规则通过时退出码为 0，否则为 1。模型名记录在启动日志，案例版本为 v1。比较时应保留两次日志，一次只改变一个变量；本次尚未实现自动版本对比或 P1/P3 工具轨迹评估。
