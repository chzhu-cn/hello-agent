# Hello Agent 技术学习路线

日期：2026-09-12

关联文档：[项目需求文档](requirements.md)

## 1. 学习目标与路线

以理解 AI Agent 为核心，先使用模型 SDK 手写不同 Pattern（设计模式），体验各模式如何组织任务；再用不同框架逐个实现相同的 Pattern，理解框架的价值与代价。

技术路线按以下顺序推进：

1. **SDK 手写**：使用现成模型 SDK，自行实现 Agent 的消息管理、工具执行、运行循环与模式逻辑。
2. **Pydantic AI**：逐个实现同一份 Pattern List，与 SDK 版本对照。
3. **LangChain**：逐个实现同一份 Pattern List，与已有版本对照。
4. **LangGraph**：逐个实现同一份 Pattern List，与已有版本对照。

先完成一条技术路线内的学习项，再进入下一条路线。每次只推进当前学习步骤。

## 2. Pattern List

以下顺序按本项目的学习递进安排，不代表各种模式存在普遍固定的难度排名。实际难度取决于案例和实现范围。

| 编号 | 学习项 | 核心体验 | 基本完成标准 |
| --- | --- | --- | --- |
| P0 | 基础：模型调用与工具调用 | 理解请求、响应、工具参数、执行与结果回传 | 完成单次模型调用和一条完整的工具调用链，并能解释数据流 |
| P1 | ReAct 风格循环 | 根据工具执行结果动态决定下一步 | 支持连续工具调用、正常结束与步数上限，能观察动作和结果 |
| P2 | Plan-and-Execute | 先制定显式计划，再执行并按需要调整 | 能观察计划、执行进度及调整过程，说明与直接循环的差异 |
| P3 | Reflection / Critique | 对已有结果进行检查，并据反馈修改 | 能展示初始结果、检查反馈和修改结果，通过验收任务判断改进情况 |
| P4 | 多 Agent 协作 | 通过角色分工、任务交接完成任务 | 能说明各 Agent 的职责、传递的信息和结束条件，并与单 Agent 版本比较 |

P0 是前置基础，不单独视为 Agent Pattern。P4 是一类模式，具体拆分和首个协作形式在进入该学习项前讨论确定。

检查反馈不保证正确，应使用实际任务的验收标准验证结果。执行记录关注计划、动作、工具结果和状态，不要求输出模型内部隐藏推理。

## 4. 两个对比方向

### 同一技术路线，不同 Pattern

观察任务组织方式改变后：

- 是否更容易完成任务。
- 行动、计划与反馈如何影响后续执行。
- 模型调用次数、工具调用次数和耗时如何变化。
- 增加了哪些失败情况与控制逻辑。
- 当前任务是否确实需要更复杂的模式。

### 同一 Pattern，不同技术路线

观察框架：

- 替代了手写版中的哪些代码。
- 引入了哪些概念、默认行为和约束。
- 如何表达相同的执行过程与状态。
- 如何处理校验、异常、停止条件和执行记录。
- 带来了哪些便利、限制和调试成本。

## 5. 案例与实现原则

1. 每个 Pattern 固定任务、工具和验收标准，供四条技术路线复用。
2. 不同 Pattern 尽量沿用同一个小案例；确需调整时，记录原因与新增需求。
3. 对照实现尽量保持模型、提示词、输入数据与工具一致。无法一致的地方明确记录。
4. 允许采用各框架惯用写法，不强求代码结构相同；比较行为与实现代价。
5. 先写清晰、可运行的独立实现，出现实际重复后再提取共用部分。
6. 保留前面阶段的可运行版本，具体目录结构在实现前确定。
7. 每一步先理解概念，再完成最小实现和验证；不一次性搭建全部模式。

## 6. 每个学习项的交付物

- 可运行的实现与必要配置说明。
- 固定的示例输入、工具及验收任务。
- 关键执行记录和验证结果。
- 简短学习记录：本次概念、遇到的问题、解决方式及仍有的限制。
- 框架阶段额外记录与 SDK 版本的对应关系和差异。

验收关注任务结果和执行行为，不要求模型回答逐字一致。异常与循环限制可通过受控响应验证。

## 7. 开始实现前仍需确定

- 模型服务、模型与对应 SDK。
- 首个案例、工具和交互方式。
- 各学习项的具体任务与范围，尤其是多 Agent 协作的拆分。
- 模型调用、工具执行与检查修改的次数限制，以及超时设置。
- 代码目录组织及学习记录形式。

这些事项在对应步骤开始前逐项确定，不影响已确定的四阶段技术路线。
